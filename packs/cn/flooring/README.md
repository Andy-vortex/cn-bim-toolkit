# 地面约定包

`rules.json`：按房间类型给每间房一种缺省地面材料，意图可以逐间改；程序按固定的规则排砖、放门槛石、算数量。程序在 `src/jiazhuang/flooring.py`（只用 shapely），命令行 `scripts/flooring.py`。流水线里排在水电之后（要读地漏的位置）、建模之前：

```bash
python scripts/flooring.py build/furnish/recog.json build/ceiling/demo-mep/scheme.json build/flooring/demo --intent packs/cn/flooring/example-intent.json
blender -b --python-exit-code 1 --python scripts/make_plan_set.py -- build/furnish/recog.json build/flooring/demo-set --scheme build/flooring/demo/scheme.json --kinds plan,floor,ceiling,mep --title "{kind}"
```

## 规则表

| 键 | 内容 |
|---|---|
| `sources` | 依据：条文号（或"惯例""推断"）、自拟概括、参数、可信度、状态 |
| `materials` | 材料：图上和表里写的名字 `name`、`kind`（`tile` 地砖、`wood` 木地板、`stone` 门槛石）、规格 `size` [长, 宽]、缝宽 `joint`、木地板逐排错开板长的 1/`stagger`、损耗率 `waste`、建模时的材质类别 `category` |
| `rooms` | 房间类型（`../furniture/room_types.json`）→ 缺省材料 `material`；`wet: true` 是湿区；`need_drain: true` 是应该有地漏（卫生间、阳台），没有时报告里记一条提醒 |
| `layout` | 排砖门槛：基准矩形两侧的边砖不小于 `min_edge` 块；别处小于 `warn_edge` 块的边砖记提醒；地漏对砖中时边砖不小于 `drain_min_edge` 块；`merge_kinds` 哪种洞口两侧同材料时通铺 |
| `threshold` | 哪些门口放门槛石：`wet` 一侧是湿区、`material_change` 两侧材料不同、`entrance` 入户门 |
| `levels` | 湿区完成面比主地面低 `wet_drop`（毫米；地面铺装图图例里写一行"湿区完成面 -0.020（厨房、卫生间、阳台）"，括号里是这张图上按这个值降板的房间用途）；找坡坡度 `fall` |
| `model` | 建模时面层的顶面 `top`（离楼面，毫米）和厚度 `thickness` |
| `checks` | `area_tol_mm2`：整块 + 切块覆盖的面积和铺装区面积最多差多少 |

缺省（都是"惯例"，数值只是缺省，意图可以改）：

| 房间 | 材料 | 规格、缝 |
|---|---|---|
| 客厅、餐厅、玄关、过道（储藏和认不出的也是） | 地砖 | 800×800，缝 2 |
| 卧室、书房 | 木地板 | 1220×195，逐排错开 1/3 板长 |
| 厨房（湿区） | 防滑地砖 | 600×600，缝 2 |
| 卫生间、阳台（湿区） | 防滑地砖 | 300×300，缝 2 |

损耗率地砖、木地板都是 5%；湿区完成面低 20。

## 排砖规则

不搜索、不打分，同样的输入每次得到同样的结果：

1. **铺装区**：一间房一个区。两间房之间是不带门扇的洞口（识别结果里 `kind` 是 `layout.merge_kinds` 里的，如 `opening`）、两边材料又相同、又都是干区或都是湿区时，并成一个区通铺，砖缝从洞口穿过去。湿区和干区不并（标高不同，洞口按门口放门槛石）。有门扇的门两侧各算各的区。
2. **方向**：顺着铺装区里多数的墙：各面墙按方向（对 90° 取模，差不到 `layout.dir_tol` 0.5° 算同一组）累加墙长，取总长最大的那组里最长那面墙的方向（来源 C12）。一面斜墙再长，也顺着另外几面正交墙铺，正交墙边不切斜砖；正交户型就是横平竖直（和取最长那面墙相同）。意图写了 `dir` 照意图。
3. **地砖对中**：取铺装区里能放下的最大矩形（基准矩形）。两个方向各自试"缝对中"（中线上是一条缝）和"砖对中"（中线上是一块砖的中线），选边砖宽的那个，一样宽取缝对中。这样基准矩形两侧的边砖对称，而且一定不小于半块。基准矩形以外的部分（L 形的另一肢、墙垛凹进去的地方）顺着同一张网格铺，出现小于 1/3 块的边砖时记进报告的提醒，不再调整。
4. **湿区地漏**：有地漏时，把网格平移到地漏落在一块砖正中，前提是基准矩形四边的边砖都不小于 1/3 块；做不到就保持对中，记一条提醒。地漏的位置不动（砖缝让地漏）。
5. **木地板**：长边顺着基准矩形的长向。板宽方向同样对中（两侧收边对称、不小于半板宽）；板长方向第一排（靠一面墙的那排）从一端整板起，往后每排错开 1/3 板长。
6. **起铺点**：地砖是基准矩形中心（缝交点、砖中心或砖边中点，看两个方向各怎么对中）；地漏对砖中时是地漏那块砖的中心；木地板画在起铺的那个角上：第一排是整板时就是墙角，第一排是收边时在墙上、离墙角一排收边宽。
7. **门槛石**：门两侧只要有一侧是湿区、或者两侧材料不同，就在门洞里放一块（门洞宽 × 墙厚）；入户门（只有一侧是户内的门）也放。两侧都是干区且材料相同的门不放门槛石，门洞中线画一道压条，两边各铺各的。
8. **数量**：铺装区按网格切成一格一格（砖加半条缝；木地板一块板），整格在区里的是整块，切过的是切块；整块 + 切块覆盖的面积要和区的面积对得上（校验）。合计：地砖 = (整块 + 切块) × (1 + 损耗率) 向上取整，木地板 = 面积 × (1 + 损耗率)（㎡）。
9. **材料编号**：用到的材料按规则表里的顺序、规格、缝宽排成 F-01、F-02…，门槛石排在最后。

砖缝不存坐标：方案和 IFC 里只记方向、网格原点、缝距、错缝、起铺点，出图时 `flooring.joint_lines` 按这些参数现算（吊顶的铝扣板网格也用它）。

## 意图（可选）

不写坐标（起铺点除外），一间房一条，写了的盖过缺省：

```json
{"rooms": [
 {"room": "玄关", "start": "corner"},
 {"room": "卫生间", "size": [300, 600]},
 {"room": "R009", "material": "tile800", "dir": 90}
]}
```

`room` 写房间 id 或房名（重名用 id）。可写的键：`material`（规则表 `materials` 的键，门槛石除外）、`size` [长, 宽]（毫米）、`joint`（缝宽）、`dir`（铺装方向，度）、`start`：`"center"` 对中（缺省）、`"corner"` 从基准矩形左下角整砖起、`[x, y]` 指定起铺点（图纸坐标，要在房间里）。

一条写错（房间找不到、材料不认识、键不认识、数不对、起铺点在房外）只在报告 `errors` 里记一行，写错的那一项不用，其余照做，退出 1；意图结构不对退出 2。`--unit U1,U2` 只重做这几户，别的户以前的地面原样保留；户号不在识别结果里退出 2。公共部分的房间不做。

## 输出

方案的 `flooring`：

- `zones`：每个铺装区 `{id, rooms, unit, material, size, joint, wet, level, polygon, holes, dir, origin, pitch, stagger, start, start_kind, edges, base, quantity, notes, source, code}`；`id` 是 `FZ-<第一间房 id>`，`level` 是完成面离楼面（湿区 -20），`edges` 是基准矩形两头边砖的宽（`u` 沿铺装方向，`v` 垂直方向；木地板只有板宽方向 `v`），`quantity` 是面积、整块、切块、损耗率、合计。
- `thresholds`：门槛石 `{id, door, rooms, unit, polygon, width, depth, reason, code}`。
- `strips`：压条 `{id, door, rooms, unit, line}`。

`report.json`：`rooms`（每间房分到的区、材料、来源"规则"或"意图"），`layout`（每个区的材料、方向、起铺点、边砖、数量、提醒），`notes`（提醒：小于 1/3 块的边砖、地漏落不到砖正中、卫生间阳台没有地漏，不算错），`errors`，`violations`：

| check | 查什么 |
|---|---|
| `no_material` | 有房间没分到材料（规则表里这类房间和 `other` 都没写） |
| `no_rooms`（errors） | 一间房都没做：房间都没有户号（`unit`）或都是公共空间 |
| `area` | 整块 + 切块覆盖的面积和铺装区面积对不上 |
| `threshold` | 门槛石和门对不上：该放的没有、不该放的有、位置和门洞不一致（和生成用的是同一条规则，查的是数据过时或被手改，不是规则本身） |
| `drains` | 湿区排砖时用的地漏和方案里现在的地漏对不上（水电在地面之后重跑过）：重跑本命令 |

建模时每个铺装区、每块门槛石一个 `IfcCovering`（FLOORING），顶面在楼面 + 区的标高 − 1mm、厚 10mm（上面没有楼板，出图时在门扇、家具二维符号之下），材质"地砖 800×800""门槛石"这样按材料，属性集 `JZ_Flooring`（`Part` 铺装区 / 门槛石、编号、材料、规格、缝宽、方向、网格原点、缝距、错缝、起铺点、房间、标高、面积、整块、切块、损耗率、合计、压条所在的门；门槛石记门、尺寸、原因）。

## 出图

`make_plan_set --kinds ...,floor` 出地面铺装图（排在平面布置图后面）和地面材料表（排在门窗表后面，每种材料加规格一行、给总量，另出 `地面材料表.xlsx`；每个区的面积、整块、切块、边砖宽、提醒在 `地面分区明细.xlsx`），见 `../drawing/README.md`。方案没有 `flooring` 时 `--kinds floor` 退出 2；方案里的地面数据和现在的门、地漏对不上（上面 `threshold`、`drains` 两项）时 `make_plan_set` 退出 1，不出图。

## 已知限制

- 只有整块方砖、长方砖、木地板三种排法；没有拼花、斜铺、波打线。
- 基准矩形取轴向最大矩形，斜墙多的房间退回外包矩形。
- 现在的识别结果（dxfplan）不产生"不带门扇的洞口"，通铺只在别的识别来源或手写的识别结果里出现；同一间房的客厅、餐厅本来就是一个区。
- 门槛石、压条只看门两侧的区；门槛石高出湿区多少不建模。
