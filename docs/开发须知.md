# 开发须知（踩过的坑）

给参与开发的人看的技术笔记：每一条都是实际碰到过的问题和现在的处理办法。

## IfcOpenShell / Bonsai

- **`blender -b --python 脚本` 里脚本抛异常，Blender 照样返回 0**：命令一律加 `--python-exit-code 1`（异常时返回 1）。脚本自己退出（argparse 的 `--help` 返回 0、参数错返回 2）不受影响。脚本参数写在 `--` 后面，`--` 前面是 Blender 自己的参数；脚本按 `argparse(allow_abbrev=False)` 解析，拼错的选项直接报错，不会被前缀匹配成别的选项。
- **单位不统一**：
  - 用米（SI）的：`geometry.add_wall_representation`、`add_mesh_representation`、`edit_object_placement` 的矩阵。
  - 用项目单位（毫米）的：`geometry.add_door_representation`、`add_window_representation`，以及手工构造的 `IfcCartesianPoint`、拉伸实体。
  - 门窗传错单位，尺寸会缩成千分之一，平面上也就看不到开启线。
- ifcopenshell 0.9 的接口按模块调用（如 `api.root.create_entity`），**调用前要先 import 对应子模块**。
- `entity_instance` 上不能挂自定义 Python 属性，元数据另外放在字典里；比较实体用 `.id()`，不要用 `is`。
- 双扇窗（`DOUBLE_PANEL_*`）要额外传扇参数，暂时都用 `SINGLE_PANEL`。
- **改了视图宽高后，出图前必须把 `scene.render.resolution_x/y` 同步成 `update_camera_resolution()` 的结果**，否则隐藏线（投影）部分按旧画幅计算，会整体错位。
- **改完宽高不要马上重新激活同一张视图**：Bonsai 会从 IFC 读回旧尺寸，还可能导致 Blender 崩溃。做法是在 `render_view` 里激活之后再写回尺寸。
- 界面上的"放到图纸"操作在后台模式下要选中列表项，改为直接调用 `core.add_sheet` + `document.add_reference` + `sheeter.SheetBuilder().add_drawing/build`。
- 图框模板通过 pystache 渲染，读文件时没指定编码，**中文一律写成数字字符引用**（见 `tools/make_titleblock.py`）。
- **比例下拉只有 1:1～1:5000 的常用档**，1:150、1:300 要设 `diagram_scale="CUSTOM"` + `custom_scale_numerator/denominator`。
- 标注对象：`DIMENSION` 是曲线对象（写 spline 点）；**`LINEWORK` 是网格对象**（`mesh.from_pydata` 写顶点和边）。
- **改了标注的 Blender 曲线/网格，IFC 里不会自己跟着变**：`core.add_annotation` 建的标注在 IFC 里只有默认几何（原点处一段竖线），出 SVG 时 Bonsai 用的是 Blender 对象，所以当次出的图是对的；但保存后的 IFC 里所有尺寸、轴号圈都是那段默认线，重新打开或在 Bonsai 里重出图就坏了。保存只同步位置（`sync_object_placement`），不同步形状。改完几何要调 Bonsai 的 Update Representation（`bpy.ops.bim.update_representation(obj=…)`，即 `tool.Geometry.run_geometry_update_representation`，见 `annotate.commit`）。它写回 PLAN_LEVEL/FALL/SECTION_LEVEL 时固定用 `Model/Annotation/MODEL_VIEW` 上下文，模型里没有会报 `'NoneType' object has no attribute 'ContextType'`，先用 `tool.Drawing.create_annotation_context("MODEL_VIEW")` 补上。每个标注多花约 60ms；选中一批一次调用只快约四分之一。核对办法：保存后的 IFC 里每张视图的 DIMENSION、LINEWORK 不同几何数应等于对象数，重新打开 IFC 重出同一张视图，标注几何逐个一致。
- 视图过滤：`EPset_Drawing.Include/Exclude` 用 ifcopenshell 选择器语法，**逗号是"且"，加号是"或"**。例如只画某个单元：`IfcElement, JZ_Zone.Block="K1"`；排除多类东西时，带属性条件的那组要用 `+` 隔开。Include 的结果还会再和相机范围取交集。
- 样式表：Bonsai 只认一个 `StylesheetPath`。本仓库的 `cn.css` 只放覆盖规则，`drawset.configure_project` 在出图时把本机 Bonsai 的 `default.css` 和它拼成一份写到输出目录的 `work/cn-combined.css`。
- 中间文件的位置：Bonsai 0.9 从 IfcProject 的 `BBIM_Documentation` 读 `DrawingsDir`、`SheetsDir`、`LayoutsDir`，以及 `StylesheetPath`、`MarkersPath`、`SymbolsPath`、`PatternsPath`、`ShadingStylesPath`（都相对 IFC 所在目录），不写就用偏好设置的缺省值（输出目录顶层的 `drawings/`、`sheets/`、`layouts/`）。`drawset.configure_project` 把它们都指到 `work/`（`drawset.WORK_PATHS`），输出目录顶层只留交付物。
- 出 PDF 用 Edge 无头打印，SVG 内嵌进 HTML，并加 `@page{size:420mm 297mm}`，不用 Inkscape；HTML 的 `<title>` 就是 PDF 的文档标题（写"图号 图名"）。Edge 路径、打印和截图只在 `printing.py` 一处（Edge 取环境变量 `JZ_EDGE`，否则在 PATH、Program Files 里找）；临时打印页打印成功后删掉，失败时留着并记 `JZLOG pdf FAILED`；成功与否看输出文件是否新生成（打印前先删掉旧文件）。没打出来的张数记在 `printing.FAILED`，入口脚本最后用 `printing.done` 收尾（见 agent 接口约定）。
- Blender + Bonsai 的 Python 环境里自带 shapely 和 ezdxf（Bonsai 的依赖），检查器直接用；**没有 YAML 库**，所以规则文件用 JSON。
- **在 Blender 里改一个还没加载进 Bonsai 的 IFC 文件时，Bonsai 注册的 API 监听器照样会触发**：例如 `type.assign_type` 会去按类型重建门窗洞口，并访问 `tool.Ifc.get()`（这时是 None）报错。这种场合调 `ifcopenshell.api` 要传 `should_run_listeners=False`（见 `openings.assign_marks`）。
- `type.assign_type`：类型的 PredefinedType 不是 NOTDEFINED 时，会清掉实例自己的 PredefinedType 和 ObjectType（比如凸窗的 `ObjectType="BAY"`）。之后判断类别要同时看类型（`ElementType`、类型名）。
- **门窗编号**用 Bonsai 的文字标注：TEXT 标注关联到门窗构件（`ifcopenshell.api.drawing.assign_product`），内容写 `{{Tag}}`，出图时 Bonsai 换成构件的属性值。关联了构件的标注不会因为构件不在视图里就不画，要自己筛出视图画出的构件：用 Bonsai 的 `tool.Drawing.get_drawing_elements`（`EPset_Drawing.Include/Exclude`，含 Bonsai 界面存的 JSON 写法，再和相机范围、深度取交集；去掉标注），见 `annotate.view_element_ids`。它按视图的相机对象算，相机挪过之后要先 `view_layer.update()`。
- **门窗编号**（规则写在约定包 README，代码 `openings.py`，数据 `packs/cn/drawing/conventions.json`）踩过的坑：
  - 分米取整用 `int(v/100+0.5)`，不用 `round()`（银行家舍入，650 会变成 06）。
  - 别的软件导出的 IFC，门窗局部原点不一定在洞口一角（ifcopenshell 参数化门窗的约定），可能在洞口中心；`OverallWidth` 是可选属性。洞口沿墙的起止取构件投影轮廓在局部 x 方向上的最小、最大值，宽度缺了也用它。
  - `Pset_DoorCommon.FireRating` 外部数据里常见 "0""无" 这类值，不能见值就当防火门；折叠、卷帘、旋转门按 OperationType 单独成类，不要落到平开门。
  - 外墙上的平开门不能一律当入户门（阳台、露台门也在外墙上）；没有户信息的模型分不清户内户外，不按"开向走廊"判断。
  - 规范报告引用门窗要带 Tag（图上标的是 Tag，构件名里常是建模时的占位编号），`checker._ref`。
- 文字标注的方向取对象的旋转：竖墙上的字 `rotation_euler.z = 90°`，从下往上读，和 Bonsai 竖向尺寸数字一致。
- `ifcopenshell.geom.create_shape` 出错时不要静默吞掉：构件会从墙集合和建筑轮廓里消失，悄悄影响外墙判断和编号避让（`PlanGeometry.fp` 记 `JZLOG footprint failed`）。
- **DIMENSION 的数字**：一段在图纸上长于 5mm 时居中写在线上方（竖线写在左侧）1mm 处，否则写到末端外 3mm，小段会和邻段数字叠在一起。起止符在线两侧各伸出约 2mm，数字跨过点位就压线。只画线不写数字：给标注加 `BBIM_Dimension.ShowDescriptionOnly=True`，且不写 Description。本仓库对写不下的小段改用 TEXT 错开（`annotate.dim_chain_smart`）。
- **Bonsai Schedules（xlsx → SVG 表格）**：
  - `core.build_schedule` 最后会用系统查看器打开 SVG，后台模式直接调 `tool.Drawing.create_svg_schedule`。
  - 放到图纸：`api.document.add_reference` + `SheetBuilder().add_document`（界面上的操作要选中列表项）。
  - 列宽按 Excel 字符数换算（1 字符 ≈ 1.852mm），行高按磅；合并单元格的宽度算错（按首列宽乘列数），不要用合并单元格。
  - 自动换行按同名 CSS 的 `--font-width` 估字宽（默认 0.45 按西文估），而且只在空格处断。中文要设 1.0，自己在可断处补空格、自己算行高（`schedules.write_table`）。
  - Bonsai 断行是 `textwrap.wrap(width=列宽 // 字号, break_long_words=False)`：按字符数贪心排，**只把 ASCII 空白当断点**，会把短行并起来。只"在标点后补空格"的话，相邻两行加起来不超过一行宽就会被并成一行（行内露出空格，"原图编号 FM"被拆到两行），没有空格的长串会横向出格。做法（`schedules.wrap_lines`）：自己按同样的字符数先断好行，行与行之间放一个空格，行内的原文空格换成不断开空格（U+00A0，textwrap 不在它那里断），每断一行都保证"本行 + 下一行第一段"超过一行宽，这样 Bonsai 不会并行；没有可断标点的长串在 `/`、空格后或编号串边界强制切开。textwrap 还会断在连字符后面，切段时要切得一样细。
  - 喂给 Bonsai 的 xlsx 带了断行空格，不能当交付数据，和它的同名 CSS、Bonsai 画的 SVG 一起放 `work/schedules/`；交付另写一份原文 xlsx 放输出目录顶层（`schedules.write_delivery`：表头加粗、细边框、冻结表头）。
  - 同名 CSS 会随表格嵌进整张图纸，`text {…}` 这类选择器会改掉图框的字体，只能写 `text.schedule`、`rect.border`。
- 图框里的指北针是 `data-type="grid-north"` 组（Bonsai 按项目网格北旋转它），图框模板固定画在每张图上；表格类图纸要用另一个不带它的图框（约定包 `A3-CN-TABLE`，`core.add_sheet(titleblock=…)` 按 `TitleblocksDir` 里的文件名找）。
- Bonsai 出图只在输出目录里新建或覆盖文件，不删旧的：图纸张数变少时（门窗表从两页变一页）旧图纸还留在 `work/sheets/`、`work/layouts/`，出图前要自己清掉（`drawset.clean_outputs`）。
- 视图标题（"平面布置图 1:50"）的图名取图纸上文档引用的 Name；不写的话用文件名，而 Bonsai 生成文件名时会去掉"～"等字符。放图时把 Name 写上（`drawset.make_sheet`）。
- SheetBuilder 写出的图纸 SVG 里中文是数字字符引用（`&#26680;`），后处理按反转义后的内容比对。
- PNG 预览也用 Edge 无头：`--screenshot`，`--force-device-scale-factor` 控制分辨率（`printing.screenshot`）。
- 图纸上哪里空着（墙体图例找空地）也用 Edge 量：`--dump-dom` 跑页内脚本，量每个图形元素的外框（和各层 clip-path 取交，字按实际字体），读回 JSON（`printing.dom_json`、`drawset._drawn_boxes`）；再把可放图区按 0.5mm 划格、标出占用，用累加和表一次算出每个位置放不放得下（`drawset._free_spot`）。不要按模型外包估：尺寸、轴号只画在有轴的地方，空地形状不规则。
- **视图取构件、裁剪都只按相机范围**：构件的包围框和相机框相交就整个画出来（`tool.Drawing.get_drawing_elements` / `get_elements_in_camera_view`），IfcOpenShell 的 SVG 序列化不裁剪，超出相机的部分在排图纸时由视口的 clipPath 裁掉。Bonsai 没有"模型裁切框 ≠ 相机范围"的设置。分段图要把模型裁在切口上、框外还要写尺寸和轴号，做法是相机照常留边，出图后给视图 SVG 里的模型线组（class 含 `target-view-` 的 `g`）加一个 clipPath（`drawset.add_view(crop=…)`、`_clip_model`）。裁切框一定要存进 IFC（视图的 `JZ_View` 属性集，相对相机中心），出图时从 IFC 读；只存在脚本内存里的话，重开 IFC 重出，墙会越过折断线画进尺寸区。Bonsai 界面里的"生成图纸"不认这个属性集。不要再用 `Include=JZ_Zone.Block=…` 按归属挑构件，跨切口的墙会只画在一张图上。
- **排图纸时 Bonsai 给视图 SVG 里的 id 加前缀**（`d<编号>-`，`sheeter.ensure_drawing_unique_styles`），只同步改 `style`、`filter` 属性和 `<use>` 里的 `url(#…)`；自己加的 `clip-path="url(#…)"` 会断链，要写成 `style="clip-path:url(#…)"`。
- 视图标题模板是 `<LayoutsDir>/assets/view-title.svg`（本工具链是 `work/layouts/assets/`；没有才拷 Bonsai 自带的：编号圈、两行排、50mm 宽，长图名被裁掉）。约定包根目录的 `view-title-CN.svg`（`tools/make_titleblock.py` 生成：图名、比例同一基线，图名下粗线，没有编号圈）由 `drawset.configure_project` 出图前拷过去。**不要放在 `titleblocks/` 里**：Bonsai 把 `TitleblocksDir` 里的每个 svg 都列成可选的图框。模板宽度只是裁切框，视图标题在视图下方的位置写在排版文件（layouts）里，图名下粗线的长度出图后按图名改写（`drawset.make_sheet`）。
- 排好的图纸 SVG 里，视图的样式规则都被加上了 `.d<引用 id>` 前缀类（`sheeter.ensure_drawing_unique_styles`）：在图纸上另画、想吃到 cn.css 的东西（图例里墙体的色块）要带上这个类（`drawset.add_legend`）。标题栏、视图标题的模板只用自己的类名（`tb-s`、`tb-proj` 这类），不要写 `text{…}` 这种会波及整张图纸的选择器。
- 现成可用的标注类型：`BREAKLINE`（网格对象，每条边中点画一个折断符号，分段图切口用）、`PLAN_LEVEL`（曲线对象，楼面标高）。PLAN_LEVEL 自动算的数字是相对所在楼层的 z、按项目单位（毫米）格式化，国内要三位小数的米，所以用 `BBIM_Dimension.ShowDescriptionOnly` + `Description` 写字（`annotate.level_mark`）。给标注加 `EPset_Annotation.Classes` 可以挂自定义 CSS 类（组合平面图的分区线 `jz-zoneline`；只有数字字母的小字 `num`，Bonsai 的字号档只有 small/regular/large/header/title 五个，`edit_text_font_size` 不认别的，所以 `annotate._apply_size` 直接写类名）。标高符号等 marker 来自 BBIM_Documentation 的 `MarkersPath` 指的文件，那个位置有文件时 Bonsai 不再拷它自带的（`svgwriter.prepare_resource_path`），所以 `configure_project` 先写好：Bonsai 自带的 markers.svg，同 id 的换成约定包 `markers-CN.svg` 里的；排图纸时 Bonsai 给 marker id 和 CSS 里的 `url(#…)` 一起加 `d<id>-` 前缀，同 id 覆盖不受影响。marker 用 `markerUnits="userSpaceOnUse"`（图纸毫米），不随线宽变；标高符号 `orient="0"`，不随线的方向变。引出线（TEXT_LEADER）的端头 `leader-marker` 也这样换成圆点。
- **按纸面大小画的点位符号**（symbols.json 带 `paper_scale` 的插座、开关、筒灯、地漏、紧急呼叫、监控）：模型线按实际尺寸投影，1:150 时只有 1:50 的三分之一大，相机的 TargetScale 在出图里不起作用。Bonsai 0.9 的 SYMBOL 标注画成 `<use href="#符号键" transform="translate(…) rotate(…) scale(对象缩放)">`，单位是纸面毫米、和比例无关，符号定义来自 `SymbolsPath`。所以 `drawset.add_view` 给视图里（裁切框里）每个这种点位建一个 SYMBOL（放置抄点位的，`EPset_Annotation.Symbol` 写符号键，`assign_product` 关联到点位），这些类型再加进视图的 Exclude；`configure_project` 把 Bonsai 自带的 symbols.svg 加上 `symbols.svg_defs` 生成的定义写到 `SymbolsPath`（同 id 替换，做法同 markers）。Exclude 要按类型排除（`IfcLightFixture, query:"type.Tag"="cn_downlight"`），按类排除会把同类里没有 paper_scale 的吸顶灯也去掉；选择器里 query 的键带点，要加引号。比例正好是 1:paper_scale 时不换，图面和以前逐字节相同。被 Exclude 掉的点位 `get_drawing_elements` 里没有，`annotate.view_element_ids` 要把 SYMBOL 关联的点位加回来（`annotate.paper_symbols`）；避让按图上的笔画算（`_paper_outline`：放大 den/paper_scale 倍，两侧各 0.2mm，圈起来的连里面），不用外框，开关斜线旁边的空地还能写字；房间名、门窗编号把这些笔画当硬障碍（`paper_shapes`，和墙同一级），不和床、家具一起算代价。放大以后符号会压进相邻的墙、伸进隔壁：`annotate.paper_pose` 用 shapely 量每种转角和变体（镜像、画到插入点一侧）的笔画压墙、出房间、压门扇的长度，挑干净的（只比这三项时，转 90° 的开关压门扇反而少，就被转到离墙 0.7m 的门扇范围里了，所以不转向的变体里有不压墙、不出房间的就不转向）；Bonsai 的 `<use>` 只有 translate/rotate/scale，scale 取对象的 x 缩放、当成整体缩放，镜像放置画不出来，所以镜像和挪到一侧都做成单独的定义（符号键加后缀，`symbols.VARIANTS`），图例、高度标注按去掉后缀的键（`symbols.base_key`）。`_clip_model` 给每个 `<use cn_…>` 包一层不带 transform 的 g 再加裁切框的 clip-path（clip-path 按引用它的元素自己的坐标系算，直接加在带平移、转角的 `<use>` 上会裁错地方）。排图纸时 Bonsai 给 `<use>` 的 href 也加 `d<id>-` 前缀；字下墨迹、文字压线这类检查要把 `<use>` 展开算（`elementsFromPoint` 只返回 `<use>` 本身）。
- 标注的先后：后放的文字只避开已经登记过的文字。分段图里先写门窗编号（要贴着洞口，位置约束最多），再写点位高度、楼面标高（要一块空地），再写房间名（在本房间里找空地，可以折行、竖写，最灵活），再画尺寸（尺寸数字避让放在室外的编号；尺寸界线最后画，遇到数字断开），最后画切口折断线（折断符号避开已写的字）；小段尺寸数字和 Bonsai 写的尺寸数字也登记进占位表。房间名先放的话会占掉门边的空地：1:150 的密集核心筒里试过，引线编号多了一倍，还有门窗标不上，所以房间名放在编号和标高之后（点位符号按纸面大小画以后又试过只让小房间的房名先放：小卫生间的房名不压符号了，但编号改压符号、核心筒里的引出线拉长到 15～30mm，没采用；现在只让纸面上小的房间外墙上的窗编号先试室外）。只写名字的小房间、走道的房名先占位、不写字（`space_labels(reserve=True)`，用 `_label(dry=True)` 找房名会写在哪，登记进 `_RESERVE`），窗的编号在那间房里先不占它（`opening_tags` 的 `use_res`），找不到再照常；门的编号和引出线也避开的话，核心筒里的井门编号会挤到别的门前、离别的门更近，小卫生间的门编号挤到隔壁居室的房名旁边，所以只对窗生效。房间名分两遍写：先写房间里有不压线写法的（含贴着线的），剩下的小房间再从房外引出（`annotate._place_labels`），免得引出的字先占了别的房间名的位置。Bonsai 居中写的字（BoxAlignment center）画出来比按字号估的字框偏上约 0.12 个字高，所以贴着线放时字顶离上面的墙要多留（`WALL_GAP_MM`），字底可以贴着下面的墙。小段尺寸数字的引出线也用 TEXT_LEADER（`annotate._dim_leader`），字按"中线"对齐在折线第一点：第一点放在这一排的基线以上约 0.22 个字号，墨迹才和同一排底边对齐的数字齐平（放在 0.3 个字号时字顶碰到相邻一道尺寸线）；检查脚本按"字是数字的 TEXT_LEADER"认它（`placecheck` 的 dim_leader，`leadercheck` 记为 dim，不算房间名的引线）。尺寸数字估的字宽（`schedules.text_mm`）比墨迹宽约两成，两根轴线之间正好放下的数字要按墨迹宽（`DIM_INK`）量才判得出放得下。
- 门窗编号放哪：只罚分压不住，要硬约束（约束本身写在约定包 README，代码 `annotate.opening_tags`）：压洁具、家具、点位罚 60 分时，只要 8mm 内没有干净的位置，罚分照样被接受，编号就写在坐便器上，所以压它们的位置先整个排除，放宽距离、室外、引出线都试过才退回去（记日志）；可放位置少的门窗先放；平开门的开启范围按扇形算（扇形外的角上能放字）；点位、洁具的避让外框要并上类型的二维符号（Plan/Body），三维 Body 盒子比画出来的符号小得多。实在放不下用 Bonsai 的 TEXT_LEADER 引出线：引出的字只写在洞口两侧不隔墙的地方（`annotate._cells` 用墙和门窗洞口把楼切成一块块不隔墙的地方）；旁边本来就没有合格位置的马上画（排在最前，不然走道里的空地先被别的编号占满，只好隔墙写），只是被已写的字挤掉的等别的编号都放好再画；先画的引出线尽量不占后面门窗最好的位置。引出线登记进占位表，后放的房间名不压它。引线的圆点取洞口中点、字那一侧的墙面上：取洞口外框上离字最近的点会落在门边墙角，0.8mm 的圆点被墙的涂黑盖住。竖写的引出线编号：Bonsai 按对象的旋转定字的方向，所以对象转 90°、线的点按对象坐标写（`annotate._leader`）。TEXT_LEADER 的曲线可以有多个点，Bonsai 按折线画、字写在第一点：引线从字端顺着字引出一小段再折过去（`annotate._leader_path`），圆点不在字端以外时这一端不能引，换位置。

## 读 DWG / 天正图纸

- ezdwg 的 `to_dwg` 只接受 DWG 作为输入；要从 DXF 生成 DWG，用 LibreDWG 的 `dxf2dwg`。
- LibreDWG 读 R2000 的中文会输出成 `\U+XXXX` 转义，需要再解码。
- **天正 T6 格式的对象（TCH_*）代理图形是空的**，LibreDWG、ezdwg、不带天正插件的 AutoCAD 都看不到天正的墙、门窗、文字、尺寸。要先用天正"导出 T3"，或用能打散天正对象的看图软件"另存为 DXF"。ACadSharp 社区的天正解析补丁对 T6 基本不起作用。
- 打散后的图层规律（以实测的一张住宅图为例，其他图要核对）：
  - 墙在 `WALL` 层，柱在 `COLUMN` 层；门窗是 `WINDOW` 层的块，门块名含 `DORLIB`，窗块 `$TCHSYS$WIN2D`。
  - 门窗块：插入点 = 洞口中心（在墙中线上），块 X 轴沿墙，|X 比例| = 洞宽，窗的 |Y 比例| = 墙厚。
  - `WINDOW` 层还有**散线**：洞口两侧的窗台线、推拉门线、凸窗外轮廓。必须加进线网，否则房间闭合不了。
  - 房间名在 `PUB_TEXT`；户型名是两段文字："A-1" 加右边的"户型"。`面积线` 层的小闭合框可能是管井，不能当户界。
  - 轴线在 `DOTE` 层，轴号在 `_AXISO` 块的属性里；挤在一起的轴号天正会上下/左右错开放。
  - 门的开启方向：开启弧的圆心 = 铰链，弧离洞口中心最远的端点 = 门扇打开后的位置。**镜像块的弧在 OCS 里**，圆心要 `arc.ocs().to_wcs(arc.dxf.center)`。块里没有弧 = 推拉门，两段弧 = 双扇门。
- `tools/make_demo_floor.py` 按上面的规律写一张合成的标准层 DXF（一梯四户，自动分段三段；`--scheme` 再写两个分区加点位的方案，分区图是 1:150；开关放在门边锁舌一侧，插座、地漏等点位避开门洞宽度及两侧 0.2m，挪不开就不放，自检不过退出 1，不留上一次的 scheme.json）：仓库不放真实图纸，改识别、出图时拿它在公开环境里复现问题。
- ifcopenshell 参数化门：门框占局部 y∈[0, 墙厚]，门扇向 +y 开；`SINGLE_SWING_LEFT` 铰链在 x=0 端，`RIGHT` 在 x=宽 端。

## 平面识别（`dxfplan.py`）

- 思路：墙线 + 柱 + 窗框线 + 每个门窗洞口补一条中线封口 → shapely 打断成网 → `polygonize` 得到所有闭合面；含房间名文字的面是房间，边界大部分落在墙线上的细长面是墙。
- 分户：从"户型"文字所在的面出发，穿过非墙边界做多源同步广度搜索，碰到公共空间（前室、通道、电梯……）就停；同时被两户到达的面归公共。
- 凸窗没有门窗块：是贴着外轮廓、不含窗块的碎面连通块；它和房间之间隔着被判成墙的窗台条，按距离找房间。凸窗台（短边 <0.8m）不能算空间。
- **凸窗的碎面连通块里还会并进墙角凸出、侧面切角之类的小碎面**：宽度要按最大那块（窗扇所在的主体）沿长边的范围算，轮廓只留主体沿墙范围内的碎面（窗台条、窗框条）。取整个连通块的外接矩形会宽出 120～400mm；取墙缺口宽更不对，凸窗常装在整个开间宽的墙缺口里。
- 楼面可能被变形缝分成几段，外轮廓要保留所有大块，不能只取最大的一块。
- 识别出的墙段在洞口处本来就断开，所以 IFC 里的门窗不挖洞（没有 IfcOpeningElement）；这种模型的尺寸标注用 `annotate.grid_annotations`（读 IfcGrid），不用 `three_chains`。三道尺寸的第一道（洞口和窗间墙）按门窗构件的位置和宽度沿外墙投影：洞口中心沿墙法线两边各探一点，恰好一边在建筑轮廓外的是外墙门窗；从外墙面往外看被楼体挡住的不标（`openings.PlanGeometry`、`annotate.facade_openings`）。
- 门窗的墙厚要在洞口两侧的墙垛上量：门窗自身的框厚（窗框 80）不是墙厚；墙垛一侧可能正好是垂直相交的墙，取两侧量到的较小值。
- 建筑轮廓（墙、空间、门窗合并）可能是 MultiPolygon（分开的楼块、宽变形缝），几何判断用 `.boundary` 不用 `.exterior`。
- **天正门窗编号导出 T3 后常被拆成同一基线上的几段 TEXT**（如 "FM" "丙" "1221"），不能给每樘门窗取最近的一段：一段文字会被分给好几樘，防火门丢了等级，普通门反被标成防火门。先按阅读方向（文字自身的 X 轴）把同一基线上首尾相接的碎片拼回完整编号：前一段文字外包末端到后一段起点不超过 1 个字高（不要用插入点之间的绝对距离，字高一变就拼不上，防火门又丢等级；前一段以数字结尾、后一段以字母开头的不拼）。没有代号的串（"1121""乙1121"）不算编号（`markcode.parse`），再和门窗（含散线凸窗）一对一配对：文字方向与洞口所在墙平行，按距离全局从近到远贪心，一个编号只给一樘（`dxfplan.join_labels`、`match_labels`）。
- 识别结果没有门窗高度。原图编号的宽度位与识别洞宽相差 ≤1dm 的才采用（`markcode.fits`）；拆改改了洞口宽度的，原图编号说的是改前的洞口，一律不沿用（`plan2ifc._orig_label`，所以 `plan2ifc.build` 传拆改前的识别结果，拆改后的几何从方案的 `after` 取）。采用的编号直接当 Tag（`openings.orig_label`；同一编号仍须同类别、同尺寸），高度取编号后两位，记 `JZ_Opening.HeightSource="原图编号"`；对不上的不采用，原文留在识别结果的 `label_raw`，门窗表备注待核。没有编号的按规则生成编号、用默认高度，门窗表备注"高度为默认值，待实测"。代号 FM/FD/FH 带甲乙丙的记防火门等级；FD、FH 各家含义不一，图上没写清时门窗表备注"含义待核"。
- 方案 JSON 的 `after` 是排方案时识别结果的快照加拆改；识别结果更正后，要把更正同步进 `after`（只改拆改没动过的字段），否则出图仍用旧数据。
- 整层太长、一张 A3 放不下 1:100 时，`scheme.split_zones` 沿 x 方向切成几段出分段平面：
  - 切口优先选楼块之间的缝（变形缝，两段各画到自己那块楼的外墙面，两边都按外墙出三道尺寸），再选整进深都落在墙上的轴（分户墙），都不合适才取离等分点最近的轴；段数取最少，但每段（含内部切口外伸的 500mm）都要放得下，放不下就加一段。不能"切口吸附到最近的轴再去重"：两个等分点吸到同一根轴时段数会悄悄变少、段长超限。
  - 段名用切口轴号（"1～14轴"），图面范围 = 左右切口之间、内部切口一侧外伸 500mm，图名和图面一致；切口处画折断线、注"接 A-03"，切口轴的轴号两张图都画。总图（组合平面图）上画分区线、注各段图号，作为组合示意图。
  - 自动分段只写 `JZ_Zone.Block`，**不写 `rooms[].zone` / `JZ_Space.Zone`**：那是设计分区，规范检查的分区规则按它查。归属规则只有一份（`scheme.zone_at`，房间按标注点、墙按顶点平均、门窗按洞口中心），房名只在标注点所在的那一段写。
- 外开的平开门（入户门常见）门扇扫到外轮廓（墙和房间，不含门窗构件：`PlanGeometry.building` 并了门窗，开到 90° 的门扇也在里面）以外时，`block_plan` 把外包并上门扇，这一侧的各道尺寸、轴号排到门扇以外，比例按加大后的外包算；尺寸量的仍是墙。裁切框外墙面一侧外扩着找（门扇本来就在框外），切口一侧不外扩。
- 外墙三道尺寸（口径写在约定包 README，代码 `annotate.block_plan`，没有轴网的 `three_chains` 同样）：洞口按位置取（落在本图范围里），不按分区归属取，跨切口的洞口两张图都标；某一侧只有一根轴照样画总尺寸。
- **原图常是局部轴线**（2 轴只在 H 轴以北、D 轴只在 40 轴以东）：读 IfcGrid 要取轴线两个端点，某一侧只画伸到这一侧的轴（端点离外墙面/切口 ≤0.35m），沿边位置在本图尺寸范围内，不能用容差把邻段的轴拉进来。这一侧是整栋楼的最外边时再按原图轴号放在哪一侧（`JZ_Grid.BubbleEnds`）。
- 留边按每一侧实际要画的尺寸道数和有没有轴号算，不要按"下左三道、上右两道"一刀切；放不下先收窄图例栏（最窄 44mm），最后才降比例。一套图的图例都取最窄那一栏的宽（`make_plan_set` 的 `LEG_W`），同一条图例名称在各张图上断法一致。

## 方案和拆改（`scheme.py`、`renovate.py`）

- 方案是一个 JSON（格式写在 `scheme.py` 开头）：房间新用途、分区、设施点位，有拆改时还有改后的几何 `after`、被拆的墙块 `demolish` 和清单 `changes`。没有方案时用 `scheme.from_recognition()` 原样建模（现状平面）。
- 排方案的程序建议分三段：定用途 → 拆改 → 布置设施；拆改会改变房间轮廓，布置要在改完之后做。
- 只动厚度 <180mm 的墙（按非承重隔墙对待），厚墙要动的地方只记"需结构确认"。这只是按厚度推断，**以结构图和结构专业意见为准**。
- 门洞加宽沿墙挪的时候，不能碰到第三个房间、别的洞口和垂直相交的墙（墙角）。
- 房间轮廓在门口常有一截很浅的门洞条凸出，外包矩形的角会落到房间外；找角点时要往里挪一点。
- 门连哪两个房间：从门中心沿墙法线两边各探一个点；只看门的外包贴着谁，在墙角会误判。
- 用途名不要互相包含（比如卫生间不要起一个含"卧室"二字的名字），检查引擎按关键字匹配用途。
- 拆改清单（`renovate.to_html`）不拼方案 `assumptions` 的原文：那里常有排方案时的过程备注，会带进交付物。判断依据是页脚固定的一句。

## 家具布置（`furnish.py`、约定包 `packs/cn/furniture`）

- Bonsai 家具库的类型插入点不统一：沙发、坐便、台盆在靠墙边中点、实体向 -y 伸；床、衣柜、书桌、橱柜在左下角；茶几、边几、餐桌在中心。建模时用实例的三维外包（`plan2ifc.lib_bbox`）加 `furniture.json` 的 `back` 归一到"靠墙边中点、+y 朝室内"（`furnish.lib_frame`）。库的平面二维线是 IfcIndexedPolyCurve，标注避让的 `_symbol_outline` 不认，退回三维投影，二者外框一致。
- 校验器在 `.venv` 里跑，没有 ifcopenshell：尺寸要写在 `furniture.json` 里，回归另查它和库的实际外包一致。`openings` 的 ifcopenshell 导入因此可以缺（只用 `opening_zones` 这类纯几何函数）。
- 门扇开启范围只能二维查：IfcClash 和三维投影都不报衣柜压门扇，还会把贴墙的坐便当成穿墙。扇形从识别结果算（`openings.rec_opening_zones`），和出图从 IFC 算的（`annotate._opening_zone`）是同一个函数；识别门的转角和开启方式也只有一份（`openings.rec_door`，`plan2ifc` 用它建门）。
- 使用面不能取太深：沙发前 600 会把隔 400 放的茶几判成占用，沙发用 400；床两侧的使用面从床头 600 以外算，给床头柜留位置。
- 小房间（卫生间、阳台、储藏）的通道净宽 600，别的 800（`room_types.json`、`rules.aisle_mm`）；通道按"空地内缩半个净宽后，同一块挨着门口和使用面"判。
- 识别出的房间轮廓在每个门洞处伸出一条 50～100 深的窄条：直接当墙边会把一面墙切成"900 / 50 / 1900"几段，墙边编号没法用。编墙边前把落在门窗洞口里的那条挪回墙线（`furnish._unjog`，按识别结果的洞口位置判断，真实的墙面台阶不动；shapely 的先缩后放在这里去不掉窄条）。
- 识别模型的门窗构件比墙面多出一点（ifcopenshell 参数化门的门框多出 15）：建筑外包里普通门窗只算墙厚范围里的洞口框，墙、柱、凸窗照算（`annotate._outline_fp`），否则三道尺寸的总尺寸变成 4015、多出一段 115。
- 参数化家具（`furngen`）：外轮廓同时给校验器（外包、使用面）、三维实体（`ShapeBuilder` 拉伸）和二维线外框，一份数据三处用；L 形的转角段一律先按左侧算，`side=right` 时整体镜像；水槽、灶台、台盆一律从台面左端（家具自己的左）量，一字、L 形一样。
- 总图的家具（`drawset.overview_exclude`）：1:200 按 `JZ_Furniture.Placement="活动"` 排除活动家具，比 1:200 更小的固定家具也排除（选择器认这种写法；方案里没有家具时不加，现有图的视图设置不变）。小比例下小厨房、卫生间放不下房名，固定家具照画会压字。
- 挡窗按高度和位置判断（`window_blocked`），一件家具按块分开算：床身 450，靠墙 100 的床头板 1000（`back_height`、`back_depth`，建模也是两个实体）。床头顶着窗（床头板在窗前）报，床长边贴着窗墙（只有床身在窗前）不报；碰撞也按块分层。整件按 1000 算会把床长边贴窗也判成挡窗，逼着用 `offset` 留缝去躲。窗台高识别结果没有时用 `rules.window_sill_mm`。凸窗的窗前范围按它在墙边上的洞口起止往室内取进深，不要对整个凸窗轮廓 `buffer`（两侧会各多出 300）。
- 房间摘要的 `start`（墙边起点在哪个角）要按外包半宽、半高归一后再看方位：直接从中心取角度，狭长房间的四个角会落进 S/E/N/W。
- 分段图名写成"1～6轴 平面布置图"（中间一个空格）：标题栏折行只在空格、顿号等处断，不加空格会断成"1～6轴平／面布置图"。

## 水电点位（`mep.py`、约定包 `packs/cn/mep`）

- 布点器只用 `furnish` 现成的房间、墙边、家具外框和 `openings` 的门扇；新写的几何只有"沿墙找一段空墙"（`mep._free_spot`）。规则、高度、回路上限都在 `points.json`，代码里不写数值。
- `furnish place` 重跑会去掉方案里所有带 `plan_id` 的 items（家具和点位一起）：改了家具要再跑一次 `mep.py`。`mep.py` 只去掉自己上次布的点位（`plan_id` 以点位类型开头），点位类型名不能带 `-`。
- 家具常贴着墙角摆：床、浴室柜、冰箱一侧的点位会落到房外或压墙。家具旁、背后、台面上的点位放不下就不放，单写一侧的换另一侧，插座数靠 `fill` 规则补；校验仍按 `outside_room`、`in_wall` 报。
- 开关按实物放：门洞边到墙角的墙垛放不下（`gap` + 面板宽 + 100）才放到拐角另一面墙上；房门里侧被淋浴房这类高家具挡住时放到门外那间（同一户）锁舌一侧。双扇门、推拉门没有锁舌，取墙垛长的一头。**点位位置不能跟着图面改**：试过按 1:100 纸面符号挑不压门扇的位置，结果同一份方案出 1:50、1:100 开关坐标不同，已改回；纸面符号压门扇由出图挑摆法、镜像减少，剩下的单独计数。
- 给排水点本来就在洁具背后，灯在家具上方：这些不查"被高家具挡住"。
- IFC：回路用 `IfcDistributionCircuit`（按户分开，Description 写户），开关控制灯用端口（开关一个 SOURCE 对灯一个 SINK）。`api.system.connect_port` 的 `direction` 要传 `"SOURCE"`，传 `"NOTDEFINED"` 会把端口方向改掉、关系变成双向；`assign_flow_control` 不能用（开关是 IfcFlowController，不是控制元件）。点位的 `plan_id` 写进构件的 Tag，回路、连接关系和方案对得上。
- Bonsai 出图不画回路和端口；符号库写了 `system` 的点位（地漏也是）建模时归到排水等系统，现有方案的 IFC 也会多一个排水系统，不影响出图。
- 新符号的字母（K、TV、TD、L、R、P、LEB）是折线（`symbols.json` 的 item 带 `letter`），跟着符号转；转到字会倒着读（底边朝 90°～270°，不含 90°）时 `annotate.paper_pose` 给后缀再加 `_u`，字母绕自己的外框中心转半圈（外框不变，压线照旧）；镜像变体里字母只挪位置不镜像。所以竖墙上的字只会从右侧读。
- 水电图（`make_plan_set --mep`）用平面视图作底图：灯、强电箱、挂机空调插座在剖切面以上，Bonsai 平面图不画，按纸面大小补 SYMBOL（`drawset.add_view(symbols_for=…)`）；比例正好是 1:paper_scale 时也补，接线要按 SYMBOL 的笔画截断。
- 每个视图可以有自己的样式表（`EPset_Drawing.Stylesheet`）：水电图的家具淡显只写在 `cn-mep.css`，接在合并样式表后面，别的图不受影响。
- 接线是 LINEWORK 标注（Name 写"开关 Tag→灯 Tag"，关联到开关），每次出图按 IFC 端口关系重画；画好后登记成放字的障碍（`annotate._WIRES`），所以要在点位高度之后、房间名之前画。
- 冷热水点相距 150，1:100 上纸面符号比实际大一倍：冷水、热水的圆圈画在插入点两侧（短斜线指回插入点），台盆、水槽的排水点在柜内离墙 150（实际位置），符号的圆圈往室内偏开画、带短线指回插入点。这样画仍会叠：冷、热水圆圈互相压、和排水点、淋浴地漏压（复验量出合成标准层给排水图 25 处）。所以水电图出图时同一面墙上的符号沿墙排开（`annotate.layout_paper`）：地面点位、灯、门扇和墙当不动的障碍，先按沿墙投影求挪动平方和最小的位置（单调最小二乘），排不开的再按平面实际形状一个个沿墙试；挪开的画细引线（`jz-shift`）指回实际位置，图例加"引线端点为实际位置"一行。排开的结果按视图存（`_VIEW_POSE`，`paper_symbols` 的值带视图 id），同一点位在插座图、给排水图上挪法可以不同；接线、高度标注、房名避让都按挪开后的符号算。曾为图面把排水点挪到离墙 500（出了浴室柜），已改回。
- 1:100 的小卫生间、厨房台面上点位挤，高度标注同一面墙上同类同高的只标一个（`point_heights(merge=True)`），放不下先引出，最后找不压字的空地。

## 按户出图（`unitview.py`、`make_plan_set --unit`）

- 按户不走分区、不用裁切框：出图前把识别结果和方案裁成只剩这一户（`unitview.subset`），后面当整层出，尺寸、轴号、外墙判断、门窗编号、表格自然只算这一户，也没有切口和折断线。试过把户当方案分区出（矩形裁切框）：L 形的户会框进别户的房间，户界切口的折断符号压在贴分户墙的点位上，四条边按整条边判外墙还是切口，外墙判成切口就丢了细部尺寸。
- 墙：离这一户的房间不超过 30mm 的墙段留下；识别出的墙多是短段，一段长墙伸过这一户时只取房间外墙厚以内的部分，分户墙、外墙都是全厚，别户的隔墙不留短头。
- 门窗：洞口开向这一户房间的留下。入户门另一侧的走道不在了，`is_entrance_door` 的第 ③ 条（户内对公共交通空间）在模型里认不出，会编成 M1021：裁的时候按第 ③ 条的条件（另一侧不归户、是公共空间，两侧房名不含排除词）认好，门上记 `entrance`，建模写进 `JZ_Opening.Entrance`，`is_entrance_door` 认它，编号仍是 FDM，门的名称和整层模型里相同。
- 轴线：位置在这一户外包以内（±30mm）、跨过这一户的留下；原图轴号标在哪一端是按整层定的，户里一律两端都标（户的四边都算最外边，不这样的话挨着核心筒那一侧的轴号会全丢）。
- 比例：`--unit` 时用 `unitview.DENS`，比整层多 1:60、1:80 两档，一套图的平面同一个比例。合成标准层的户 13～15m 见方，A3 上是 1:80；示例户型 1:50。1:150 也放不下时一行错（`JZLOG failed unit too large`）、退出 1：先按三道尺寸 + 轴号的留边、另加图例栏估，放不下的不建输出目录；按实际留边才放不下的（少见）输出目录里只有 model.ifc 和 work/，没有图。不给 `--unit` 时比例档不变（没有户的小平面也是 1:50、1:100…）。
- 没有分区、整层放得下 1:150 的"总图就是详图"那张平面图（按户出图都走这里）：拆除的墙照画，图例自动带"拆除"；1:200 及更小的总图才排除拆除的墙。
- 门的 Name 写的是识别结果的门窗 id，整层和按户相同；户里新编的门窗编号同尺寸撞号加的 a、b 后缀可能和整层图不同。

## 图种、顶面布置图和地面铺装图（`make_plan_set --kinds`、`ceiling.py`、`flooring.py`，约定包 `packs/cn/ceiling`、`packs/cn/flooring`）

- `--kinds` 不是只有 `plan` 或只有 `mep` 时（几种图一起出，或单出顶面、地面），图名都带图种（"U1 平面布置图""U1 顶面布置图"）；只有 `plan`、只有 `mep` 时图名、图号、目录和不带 `--kinds`（或用 `--mep`）时逐字节相同。图种表 `KINDS` 按 `KIND_ORDER` 排：平面布置 → 地面铺装 → 顶面布置 → 灯具定位 → 插座 → 开关连线 → 给排水，表格在后（门窗表、地面材料表、回路表、点位统计表）。`ceiling` 一种出两张：顶面布置图、灯具定位图。
- 流水线顺序：家具 → 吊顶 → 水电 → 地面 → 建模 → 出图。地面在水电之后：湿区要把地漏放到砖正中。吊顶在水电之前：灯的 z 跟吊顶底（`ceiling.adjust_lights`，`mep.py` 重跑时也调）；方案里没有 `ceilings` 时灯的 z、IFC 都不变。
- 改了上游没重跑下游会出错图：水电布点之后重跑 `ceiling.py` 换了模板，筒灯、灯带还在旧位置；地面之后重跑 `mep.py` 挪了地漏，排砖还对着旧地漏。`ceiling.py` 写完吊顶后，方案里已有筒灯、灯带时按 `mep.validate` 的 `ceiling_light` 查一遍（`ceiling.stale_lights`），对不上记违规、退出 1；`make_plan_set` 入口对有吊顶的方案同样查、对有地面的方案调 `flooring.check`（门槛石和门、湿区的地漏），有一处就 `JZLOG stale`（写明该重跑哪条命令）、退出 1，不建输出目录。没有吊顶、没有地面数据的方案不进这两个判断。
- 吊顶块的外圈是房间轮廓往里收（shapely `buffer(-w)`），L 形、凹凸房间自然是一整圈；收完的中间再做一次开运算（`checks.center_min_width`），窄的细长部分（进门过道）并进外圈，不留细缝；收完中间太小、净高不够都退一级（规则表的 `fallback`），原因写进报告。门窗顶：窗高没标的按"缺省窗台 + 缺省窗高"和实际窗台取大，高窗（窗台 1500）不按 1500 + 1500 算，否则卫生间的铝扣板吊顶全被判成低于窗顶。
- IFC：每块一个 `IfcCovering`（CEILING），`IfcArbitraryProfileDefWithVoids` 拉伸 `checks.thickness`，底在楼面 + bottom，材质名按 `materials.*.css`，属性集 `JZ_Ceiling`；`JZ_Space.CeilingHeight_mm` 只在方案有吊顶时写。
- Bonsai 的 REFLECTED_PLAN_VIEW 和平面同一个朝向（`svg-mirror-y` 和相机缩放 -1 抵消），画剖到的墙和窗，不画门；吊顶块是投影线，`cn.css` 里 `IfcCovering` 是灰细线，顶面布置图另接 `cn-ceiling.css` 加深。顶面图里家具、洁具也会被剖到画成黑块，所以顶面布置图的视图排除家具、洁具和插座开关类。
- Bonsai 在 RCP 视图里自己写小尺寸的数字，会叠在一起。`_dim_plan` 在 RCP 视图里缺省把数字全交给 Bonsai；视图 id 记进 `annotate.RCP_OWN_TEXT` 的（顶面布置图、灯具定位图）由我们排，示例户型的 JZ-03 不在里面。吊顶尺寸串的点要按左→右、下→上排序，否则数字倒着。
- 吊顶标高用 `annotate.level_mark`（米、三位小数）；Bonsai 原生 PLAN_LEVEL 的文字是 "+2450"（毫米），不能直接用。
- 顶面布置图、灯具定位图的视图先把吊顶块的边登记成放字的硬障碍（`annotate.ceiling_lines` → `CEIL_LINES`，`_obstacles` 读），房名、吊顶标注、尺寸数字都不压造型线，引线可以跨。造型尺寸和灯具定位尺寸的方向任意，`_dim_plan` 只管横竖，所以另写了 `_dim_free_plan`：尺寸线只画线不写字，数字自己放（本段旁 → 另一侧 → 引出），写在本房间里。
- 吊顶标注放哪（`annotate.ceiling_marks`）：依次试房内全名、房内短名、建筑外轮廓到第一道尺寸之间（约 9mm 宽，标高 + 名称竖叠约 8mm 高，常要并排写），都不行就跳过并计数（`CEIL_SKIPPED`），任何一档都不落进别的房间。面积 ÷ 边长大的块先写、从块中心找；窄带子从带子上离房间中心最近的点找，并和本房间已写的标注隔开 `ceil_mark_gap_mm`，这一档只有挨着的地方时才用挨着的。整间原顶的房间不逐间写，图例一行（`CEIL_LEGEND`）。
- 吊顶标注的引线：从标高线的一端出发（`_level_layout` 的 L 是线的高度，两端是 `lp[0]`、`lp[0] + W`），用 `_leader_path` 先顺着线引出再折，所以不回头穿过自己的字；纸面上至少 `ceil_lead_mm` 长，灯槽的端点落在灯槽带中线上（半带宽 = 面积 ÷ 边长）。端头圆点是 FILL_AREA（`jz-leaddot`），不用 TEXT_LEADER：标注是标高 + 名称两件，不是一段文字。
- 写到房外的吊顶标注，引线只穿过本房间的外墙：离别的房间 0.3mm 以上、不长于 12mm。只把别的房间往里收 50mm 来判不够，引线会沿外墙内皮穿过隔壁几间再指到本房间。
- 筒灯、灯带只在方案有吊顶时布（`points.json` 的 `ceiling: ring | slot | axis` 锚点，没有吊顶块就一个都不放、也不记 skipped），所以没吊顶的布点、IFC、图纸逐字节不变；灯带类型（`views` 为空）只在用到时建。灯带是线形点位：方案 items 多 `path`、`length`，IFC 是 `IfcLightFixture` + `JZ_LightStrip`，图上不按构件投影（视图排除），另画沿灯槽的虚线（`annotate.light_strips`）。
- 同一组的灯用 `next` 连成一串（IFC 里灯 SOURCE → 下一盏 SINK），开关连线图上一盏接一盏，开关只接第一盏。一间房几段灯带串成一组时灯带接灯带也是控制关系：从端口关系数"哪些灯有开关"时不能只认有符号的上游（灯带没有符号）。
- 筒灯的间距（`mep._ceiling_spots`）：任意两盏中心距不小于 `spacing_min`。只按"间距不超过 spacing_max"均布的话，外圈一小段折线（约 1.2m）会放两盏相距 400 的灯，拐角两头各让 end_min 的两盏只隔 566，窄过道（整条都是外圈）两侧各一排、离墙只有一百多。所以拐角处两排各让 `spacing_min / (2 sin(φ/2))`（`_end_clear`），长段先放、后放的避开已有的灯，放不下两盏的段只放一盏在正中；两段平行、相距不到 `spacing_min` 的地方只留正中一段（`_one_row`，正中是灯槽放不了灯时只留长的一排）；间距取整到 10、余数分两头（`_even`），图上 `n×s=L` 的算术才对得上。
- 一排两头到墙只差不到 `end_sym_max`（100）时取对称（`mep._symmetric`，只往里收，排不下保持原样）；同一圈里相对的两排灯数相同、可布灯长度相差不到 `align_within`（1.0 个间距）时，长的那排用短的那排的灯位（`_align_opposite`，改完仍要离别的灯不小于 `spacing_min`，不行各排各的）。规则 C26，推断。
- 量离墙要用墙线：识别出的房间在门洞处有 50～100 深的凹口，`furnish` 的墙边已经挪回墙线，IFC 的空间轮廓没有。灯具定位图量墙用吊顶块的外轮廓（`light_dims` 的 `ref`），否则门前的灯量出来差 50，被当成"不在边带正中"。
- 筒灯的纸面符号一律居中：`paper_pose` 给贴墙点位用的"画到插入点一侧"的变体（如 `cn_downlight_l`）会把符号挪开约 100，图上看像两盏不共线，尺寸界线也对不上。
- 门口开关（`mep._group_lights`）：同一个门口的各组灯合在一块面板（卧室门口的双控加上筒灯、灯带各一联成"三联双控"），超过 `panel_max` 联才加第二块；筒灯另加一块单联的话，多出来的那块常压门扇。多联双控的类型（`symbols.json` 的 `on_demand`）只在用到时建，没吊顶的 IFC 不多类型。
- 床头开关（`bed_switch`）不进门口面板的候选（`door_sw` 只取 `kind == "switch"`）。门口面板被意图删掉时筒灯、灯带没有开关，`place()` 的 skipped 里记一条提醒。
- 水电图上筒灯是开关排开时不动的障碍：`layout_paper` 里筒灯外扩 `LAYOUT_GAP_MM`，开关不贴着它；墙前有筒灯、排不开的开关（第二遍）再换摆法、挪到 `switch_shift_mm`。只在有筒灯的图上起作用，没吊顶的图逐张不变。开关和筒灯的圆圈相切时按面积量不出压着，查压符号时这一对按相交算。
- 照明分路（`mep._circuits`）装的单位是控制组（`_control_groups`：一联开关加它接的整串灯，双控两只开关接同一串算一组），整组不拆：一联开关只能断一路，按灯逐盏装满 25 盏换下一路的话，一串筒灯会分在两路上、开关和它的灯也可能不同路，回路表接不出来。同一块面板（和与它双控的开关）接的各组合起来放得下时一起装，按方案顺序装进第一路放得下的（first-fit：名额都是 1 时和逐个装满相同，插座回路、没吊顶的方案结果不变）。
- 一串灯本身超过一路的上限时在 `_group_lights` 先拆（`_split_chain`：沿串连续、组数最少、盏数尽量均匀），面板按"联数不超过 panel_max、接的灯不超过一路上限"排（`_panels`），否则 35 盏拆成的两组落在同一块面板上，这块面板必然跨两路。开关的回路跟它那一联的灯；面板各联不在同一路时另记 `gang_circuits`，`validate` 的 `circuit_gang` 查每一联。
- 回路表（`make_plan_set.mep_tables`）的点位分三列：灯具数、开关数、插座数（按点位类别 `mep.SYMBOL_KIND`；这一路的前缀没有这类点位写"—"）。只写一列"点位数"会把开关也算进去，照明回路看着超过 25。
- 灯具定位图的成排筒灯（`annotate.light_dims`）：同一条横线或竖线上、相邻两盏不超过 `spacing_max × row_break` 的算一排，一道尺寸，尺寸线和灯排平行、朝房间里面偏开 `light_dim_mm`（`_dim_free_plan(ortho=True)` → `_dim_row_plan`），连续相等的间距合成一段写 `n×s=L`。尺寸线偏得更远（6.5、8mm）压线反而更多。
- 成排筒灯只标一端到墙（`dimensions.light_dim_ends` 为 "one"）：一端到墙加各段间距已经定死这一排。成圈的各排（全在边带正中的）按顺时针只标起点那端，顺时针方向取"朝近墙的外法向顺时针转 90°"，凹进去的拐角也对；这样每个拐角只落一个小数字，两端都标时拐角处两排的首尾小段挤在一起，是数字压线的主要来源。不成圈的排两端各用 `_dim_row_plan` 排一次，取（没放下, 引出）少的那端，一样时取近的。
- 相对两排共用一道尺寸（`light_dims` 的 `partner`）：同一间房、同方向、灯数相同、灯位对齐、纸面相距不超过 `light_dim_share_mm`、两排之间没有别的灯符号时只画一道，对面那排的尺寸界线从灯朝回画到同一道线。查"每盏灯都有定位"时对面那排也算有尺寸。
- 灯具定位图的先后：先画成排筒灯的尺寸线，再画主灯的（挑墙时先找数字不用引出就写得下的那面）；然后排数字，各排的合并写法先排、首尾到墙的小段后排（`flush` 分两遍，免得拐角处一排的小段先占掉另一排合并写法居中的位置），主灯的数字沿线挪开成排的；再画不在边带正中的灯排、单独一盏的尺寸线（先试不穿过已写的数字）、排它们的数字；尺寸界线最后画，遇到字断开。数字都等这一批尺寸线画完再排，免得压着后画的线。合并写法放不下（主灯的尺寸线正好横穿过去）时逐段写。
- 主灯量到近的那面墙，尺寸线穿过筒灯符号时不换远墙（远墙常横穿整个客厅），而是 DIMENSION 照建、线加 `jz-dimgap` 不显示（只留起止符），另用 LINEWORK 画符号以外的几截（`_dim_gap_draw`，样式在 `cn-lights.css`）；只有被别的灯符号挡住、穿过已写的字或数字无处可放才换远的那面。
- 灯具定位图数字的字框（`_dim_row_plan` 的 `text_w`）和图面检查量字的办法一致：汉字一个字号宽，数字、"="半个字号；"×"在仿宋里比数字宽，按 0.75 个字号，按半个估的话合并写法的字框短了，挨着的小段数字会贴上去连读。按 `schedules.text_mm`（数字 0.55、"×"按全角）估太宽，合并写法放不下。
- Bonsai 居中写的字比估的字框偏上约 0.12 个字高：字框跟着上挪，和别的已写的字之间再隔开这 0.12 个字高，按没挪的框量时两个字才不叠。实在放不下时挑位置，压别的字和压符号一样算重（宁可压线，不让两个数叠在一起）。
- 同一道尺寸上相邻两个数沿线至少隔一个数字宽（`DIM_CHAR_GAP`：字框沿线两头各加一个字宽，再查本道已排的字框），否则 "775" "2×950=1900" 会读成一个数。
- 每个起止符登记成数字的障碍（`DIM_TICK_MM`、`DIM_TICK_PAD_MM`：尺寸线方向逆时针转 45° 的细长条，只在 `light_dims` 里登记，不是字框，不影响尺寸界线遇字断开）：写在线下（右）一侧的字墨迹离线只有约 0.7mm，沿线挪到段头时会压起止符。按圆登记不行：墙角那头的起止符一半在墙里，圆会把靠墙的小段数字挤到灯带上。
- 灯具定位图数字的引线只查不压字、符号、不出房间，可以跨造型线和别的尺寸线、界线：拐角处两排的尺寸线、界线必然交叉，查了就一个都引不出来。
- 地面面层：每个铺装区、每块门槛石一个 `IfcCovering`（FLOORING），顶面在楼面（湿区再降 20）以下 1mm、厚 10mm，上面没有楼板：高出 ±0 会把门扇、家具二维符号盖掉，盖在楼板下又不出填充，SVGFILL 填充方式会崩。方案有地面时每张图的视图都排除它（`EXCL` 加 `IfcCovering, PredefinedType=FLOORING`），平面、顶面、水电图和没有地面数据时一样；没有地面数据时 IFC、各张图逐字节不变。
- 砖缝不靠 Bonsai 的填充画（图案只能整张平移，排不了"非整砖放墙边"），也不存坐标：方案和 `JZ_Flooring` 只记方向、网格原点、缝距、错缝、起铺点，出图时 `flooring.joint_lines` 现算，每个区一个 LINEWORK（顶点、边一次写进一个网格对象：几百段线只多一次 commit）。吊顶的铝扣板网格用同一个函数（`plan_grid` 对中，缝宽 0）。
- "线让字"（`annotate.lines_avoiding`）：砖缝、铝扣板网格最后画，按已写的字框、尺寸、标高、引线（`_OCC`）和符号笔画外扩 0.5mm 裁掉；字不压线，图面检查不用为这些线开例外。起铺点记号要在写房名之前画（登记进 `_OCC`），否则房名会压在它上面。
- 铺装方向（`flooring.main_dir`）按方向对 90° 取模累加墙长，取总长最大的那组：只取最长那面墙的方向的话，一面斜墙恰好最长时（174.8°）三面正交墙全切斜砖。
- 排砖的"最大矩形"按顶点坐标切格求（`flooring.base_rect`）：L 形客餐厅用外包矩形对中时，两肢的边砖都会很窄。地漏对砖中只在基准矩形四边的边砖都不小于 1/3 块时才挪网格，挪不了保持对中、记提醒，地漏位置不动。
- 门槛石浅灰填充用 Bonsai 的 FILL_AREA 标注（网格对象一个面，`annotate.fill_area`），commit 写回 IfcAnnotationFillArea，重开 IFC 照样画。
- 地面铺装图的标注顺序：起铺点记号 → 房名（带材料一行）→ 起铺点定位尺寸 → 主地面标高 → 找坡箭头 → 门槛石、压条 → 外围尺寸 → 砖缝。房名写的是这间房的材料，写进别的房间会把材料看错，所以先放、只许写在本房间里（`space_labels(second=…)` → `_place_labels(own=True)`：不引出，最后一档也只在本房间里找）；尺寸数字可以引出、箭头可以转向缩短，放在后面。尺寸线优先选不穿过已写的字的那面墙。
- 小卫生间（1:80 下 20mm 见方）放不下逐间的标高：湿区标高写进图例一行"湿区完成面 -0.020（厨房、卫生间、阳台）"，括号里是按这个值降板的房间用途，图上看得出哪几间是湿区；和规则表降板值不同的湿区才单独标。
- 地面铺装图只留墙、门窗和地漏：家具、洁具、电器（`IfcElectricAppliance`，冰箱、洗衣机）、别的点位类和排水点（`cn_drain`）都排除。

## 规范自查（`checker.py`）

- 引擎不认识任何具体标准：规则包里每条规则写 `type`（`checker.CHECKS` 里的通用检查类型）和 `params`（用途关键字、阈值、说法）。新增检查类型时写成参数化的函数，不要把某本标准的字眼写进代码。
- 结论只有六种：通过 / 不通过 / 待确认 / 信息不足 / 不涉及 / 人工复核；一条规则取其中最坏的那项。
- 尽量只用 IFC 的通用信息（空间轮廓、构件类别和预定义类型、`Pset_*Common`、构件位置），`JZ_*` 属性只作补充（用途、分区、照护类型、一个标准层代表的多个标高）。
- 门开启净宽按洞口估算：平开门 = 洞口 − 100，推拉门（洞口 ≥1.5m）= 洞口/2 − 50。走廊净宽给区间：下限是等效矩形短边，上限是最大内切圆直径。
- 每个规则包都应配反例测试：故意把方案改坏几处，确认引擎能判出不通过。

## agent 接口约定

- 一个脚本对应一个工具（`dxfplan`、`make_plan_set`、`check_ifc`、`make_demo_set`、`furnish`、`mep`），工具参数和脚本的 argparse 同名同义（`allow_abbrev=False`，输入文件不存在、识别结果不是 JSON 对象或里面没有房间或墙、约定包缺文件（`conventions.check_pack`，一次列全）时解析参数就报错，退出码 2，不建输出目录）。读约定包的模块（`annotate`、`drawset`、`openings`、`plan2ifc`、`schedules`）都在导入时读，所以入口脚本先 `check_pack`、再导入它们；在别处直接导入、约定包又缺文件时，导入就报"约定包缺少 …"。
- 返回落盘路径和计数，不返回说明句。取进程输出里的最后一条 JZLOG（Blender 在脚本之后还会打印 `Blender quit`）：`JZLOG done <输出>`（`dxfplan` 是识别 JSON，其余是输出目录），退出码 0；有 PDF、PNG 没打出来时是 `JZLOG failed <张数> <输出目录>`，退出码 1；`dxfplan` 在 `--region` 里认不出房间或墙时是 `JZLOG failed no rooms or walls: check --region <识别.json>`，退出码 1，不写识别结果。`dxfplan` 的识别统计加 `--verbose` 才打印。`furnish place` 有违规或意图摆不了时是 `JZLOG failed <条数> <输出目录>`，退出码 1，方案和报告照样写出。
- 六种结论原样透传，不改写、不合并。
- 自查报告和拆改清单的 HTML 末尾内嵌同源 JSON（`<script type="application/json" id="data">`）：读数据读它或旁边的 `.json`，不解析表格；分组、对象名去重只在显示层。
- 免责只在技能说明里写一次。
